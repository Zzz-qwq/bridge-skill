# Bridge

**让机会不再只属于知道机会的人。**

Bridge 是一个对话 Skill。用户说出想完成的事，或一个尚不清楚如何探索的兴趣，它先回应眼前需求，再展示几条机制不同、用户可能没想到的路，并给出可尝试的第一步。实习、AI 入门和动漫兴趣是首批验证场景；娱乐与好奇心不必被转成求职任务。

## 当前状态

这是内测候选版。Skill 已在码道 IDE 中成功加载。2026-11-10 在只装 Bridge 的空白项目中，显式要求使用技能后，实习场景保持岗位方向未知并给出四条不同路径；“了解居住城市”场景先给观察、资料、社区和城市数据等入口，再随用户补充的信息调整。原样输入的自动调用仍不稳定，实习、AI 和动漫三题的历史结果见验收记录。真实用户是否发现原本不知道且愿意尝试的路径仍待验证；首批三位试用者将使用自己的真实问题。具体机会的实时核查能力仍受宿主可读取页面范围影响。

## 使用

将 [`bridge/`](bridge/) 放到宿主的项目技能目录。在码道 IDE 中，先用新对话分别做两种测试：原样输入观察能否自动调用；再明确要求“使用项目级 bridge 技能”，检验 Skill 被调用后的输出。示例：

> 我在找 AI 产品实习，每周能投入 3 小时。除了黑客松，还有什么方式能留下可展示的实践成果？

> 最近想找点好看的动漫。除了常见的热门榜单，还有什么方式能找到合我口味的作品？

Skill 的完整规则在 [`bridge/SKILL.md`](bridge/SKILL.md)。若宿主无法读取当前网页，Bridge 应标明机会状态与参与条件尚未核实，并给出仍能执行的自主实践第一步。

三道首批输入只用于检查演示流程。项目另备有[复用性盲测](复用性盲测.md)，用未写入 Skill 的改写题、跨领域题和多轮纠正题检验迁移；用户是否真的发现新入口，需要本人先说出原本知道的办法，体验后反馈，并观察是否尝试了第一步。

## 原则

- 不替用户决定人生。
- 不虚构机会、资格或成功路径。
- 区分来源事实、适配判断和尚未核实的信息。
- 让用户自己确认哪条路径是新发现，再选择下一步。

## 自检与更新

Skill 在回答前检查用户前提、路径差异、可执行第一步和来源边界；失败样例记录在验收文档中，由维护者审核后修订并回测。运行中的 Skill 不自行改写规则。[Self-Refine](https://proceedings.neurips.cc/paper_files/paper/2023/hash/91edff07232fb1b55a505a9e9f6c0ff3-Abstract-Conference.html) 和 [Reflexion](https://papers.neurips.cc/paper_files/paper/2023/hash/1b44b878bb782e6954cd888628510e90-Abstract-Conference.html) 为反馈迭代提供了研究参考；[ICLR 2024 的自纠错研究](https://proceedings.iclr.cc/paper_files/paper/2024/hash/8b4add8b0aa8749d80a34ca5d941c355-Abstract-Conference.html) 提醒我们，缺少外部反馈时单靠模型反思并不可靠。这些论文支持机制取舍，**不是 Bridge 效果已得到证明**。

## 信息范围

Bridge 可以先发现用户尚未想到的渠道，例如招聘网站之外的公司招聘页、开发者社区和社交平台，并给出可复制的搜索词。只有宿主能读取的公开页面、或用户提供的链接与截图，才能用于核对具体帖子；读不到时标为线索，不说某家公司当前正在招募。小红书[账号开放平台的权限说明](https://openaccount.xiaohongshu.com/docs/scope)目前把读取笔记列为规划中，不能把该接口当作完整的实时笔记库。
